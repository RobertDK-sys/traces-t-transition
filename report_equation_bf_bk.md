# Finding Solutions to Nf·b_f = Σ b_k

## 1. Problem Statement

We look for solutions to the equation:

```
Nf · b_f = b_1 + b_2 + ... + b_k + ... + b_Nf
```

where Nf is a natural number, all b_k are **distinct** (b_1 ≠ b_2 ≠ ... ≠ b_Nf), and both b_f and every b_k are generated by the **same formula**:

```
b_f = (asin(sign_f * abs(s2_val_f)) - 2 * k_f * pi) / log(2)
b_k = (asin(sign_k * abs(s2_val_k)) - 2 * k_k * pi) / log(2)
```

The s2_val values come from the numerical solution (via `brentq`) of the characteristic equation:

```
0 = |8·s2^6 − 24·s2^4 + 24·s2^2 − 8|^(2/3) · (24·k3^2·s2^6 − 72·k3^2·s2^4 − 24·k3^2) + 4·s2^4,  k3 = −t
```

for each natural number t, with the root s2(t) sought in the interval (−1, 0).

## 2. Two Possible Readings of the Equation

**Trivial reading (mean).** The equation literally states that b_f is the arithmetic mean of the chosen b_k values. Under this reading, a solution **always exists** for any Nf: simply pick Nf distinct values from the b_k family and set b_f = their average — without requiring b_f to belong to the family itself.

**Non-trivial reading (b_f in the same family).** This is the reading adopted here, per the user's request: b_f must be generated by exactly the same formula as the b_k (same asin/2kπ/log2 structure, with its own sign_f, k_f, s2_val_f). This constraint is far stronger: it amounts to finding a combination of Nf discrete values whose sum lands exactly — or nearly so — on Nf times another value drawn from the same grid.

A preliminary exhaustive test (Nf = 2, a table of 1200 candidate values) found **no** exact match within 10⁻⁶, confirming that the non-trivial constraint is not satisfied "by accident" — a structured search is required.

## 3. Combinatorial Difficulty and Algorithmic Choice

The problem "choose Nf distinct elements from a table of size N, plus a target element equal to their mean" is a subset-sum-type problem that grows combinatorially explosive: the number of combinations C(N, Nf) quickly becomes intractable as Nf or the table grow. Exhaustive enumeration is therefore only practical for Nf = 2 or 3 with a small table.

We therefore chose a **simulated annealing search**, which scales to any Nf:

1. Build the table of all possible (t, sign, k) triples and their associated b value, for t = 1..t_max, sign ∈ {+1, −1}, and non-zero integer k in [−k_range, k_range].
2. Initial state: Nf distinct indices (the b_k) plus one free index (b_f).
3. Iteratively minimize |Nf·b_f − Σb_k| through local moves (replacing one b_k, or changing b_f), with probabilistic acceptance of worse moves under a decreasing temperature schedule — this avoids getting stuck in a local minimum and allows broad exploration of the combination space.

## 4. Results

With t_max = 200, k_range = 15, and 150,000 iterations, the residuals |Nf·b_f − Σb_k| obtained were:

| Nf | Residual |
|----|----------|
| 2  | 5.4 × 10⁻⁴ |
| 3  | 2.0 × 10⁻⁶ |
| 5  | 6.4 × 10⁻⁵ |
| 8  | 4.9 × 10⁻⁵ |

Detailed example for Nf = 3 (best residual obtained):

- b_f = −34.02834952, with t_f = 193, sign_f = +1, k_f = 4
- b_1 = 88.42029775, with t_k = 159, sign_k = −1, k_k = −10
- b_2 = −115.76211412, with t_k = 7, sign_k = +1, k_k = 13
- b_3 = −74.74323416, with t_k = 148, sign_k = −1, k_k = 8

Check: 3 × b_f ≈ b_1 + b_2 + b_3, within 1.98 × 10⁻⁶.

## 5. Interpretation and Limitations

- **Approximate** solutions exist for every Nf tested (2, 3, 5, 8), with the residual decreasing as the table resolution (t_max, k_range) and the number of iterations increase.
- An **exact** equality would require a precise algebraic relation between the arcsin(s2(t)) values at several values of t — nothing in the current structure of the problem guarantees such a relation exists when t is restricted to natural numbers.
- Two directions for further work: (a) relax t to real values and use continuous optimization to force strict exactness; (b) further increase the table size and iteration count to reduce the numerical residual further within the current discrete setting.
